## 학습 내용
### 1. SQL 조회와 조작
- 지난 주에 진행했던 DB 및 SQL 기초에 이어 심화 단계에 들어가 기본적인 SQL에 대해서 더 자세히 알게 돼었다.
- 데이터베이스 관련한 강의를 수강한 적이 있어 크게 어렵지는 않았고, 배웠던 것들을 다시 한 번 상기하는 계기가 됐다.
    - 조회
        - SELECT 컬럼명
        - FROM 테이블명
        - WHERE 조건식
        - GROUP BY 그룹화할 컬럼
        - HAVING 그룹조건식
        - ORDER BY 정렬할 컬럼
    - 조작 (DML)
        - 삽입
            - INSERT INTO 테이블명 (컬럼1, 컬럼2, ...)
            - VALUES (값1, 값2, ...)
        - 수정
            - UPDATE 테이블명
            - SET 컬럼명 = 값
            - WHERE 조건식
        - 삭제
            - DELETE FROM 테이블명
            - WHERE 조건식
- 아울러, SQL뿐만 아니라 RDBMS의 구조와 원리에 대해서도 복습 시간에 복습을 진행하여 DB가 어떻게 ACID를 만족하는지에 대해 다시 한 번 상기하는 계기가 됐다. 
    - ACID
        - Atomicity (원자성) : 모두 다 되거나, 아예 안 되거나!
        - Consistency (일관성) : 항상 올바른 상태를 유지할 것!
        - Isolation (고립성/격리성) : 남의 작업(트랜잭션)에 끼어들지 말 것!
        - Durability (지속성) : 성공한 결과는 영원히 남을 것!

### 2. API-DB 통합 (FastAPI-SQLite)
- 본래 서비스들은 백엔드(FastAPI)와 DB(PostgreSQL, MySQL, SQLite, ...)는 별도의 프로세스 또는 기기로 분리되어 방화벽을 통해 DB의 접근을 최소화하여 보안을 강화한다.
- 쿠키즈들이 이러한 백엔드-DB 간 Data I/O를 이해하기 위해서 별도의 DB 서버 환경을 구성하여 배우기 보다는, Python 내에 자체 내장된 sqlite3 라이브러리를 통해 환경을 구성할 필요 없이 쉽게 DB I/O를 배우도록 하였는데, 좋은 선택인 듯 하다. 정말 간단하게 DB SQL을 실습해볼 수 있었다.
- 우연(?)의 일치일 진 모르겠지만, FastAPI도 Python에서 작동하는 백엔드 프레임워크로써 sqlite3와 연결해서 쓰기 매우 좋아, 백엔드 서버의 기초인 API 엔드포인트를 통한 데이터 I/O를 쉽게 실습해볼 수 있었다. 프레임워크가 아주 좋다.
- 지난 주에 배웠던 Early Return을 적용하니 코드 가독성이 매우 명확해져서 좋았다. 그냥 FastAPI 자체가 가독성이 좋은 프레임워크인 거 같기도?
- 강의에서는  @app annotation을 함수 위에 달아서 API 엔드포인트를 구성함과 동시에 그 엔드포인트로 트리거되는 함수 안에 모든 로직들이 함께 있는 구조였는데, 실습 내용은 굉장히 간단해서 가독성이 여전히 좋지만 로직이 길어질 수록 가독성이 매우 떨어질 수 있겠다는 생각이 들었다. 근데 그렇다고 이렇게 간단한 걸 책임 분리하기엔 오버엔지니어링같다는 생각이 들었다.
- 이렇게 간단할거면 PostgreSQL, MySQL같은 RDBMS는 왜 있을까 하는 생각이 들어서 조사해보다가, sqlite 자체는 PostgreSQL, MySQL와는 작동 원리가 달라 실제 서비스를 감당할 수 있는 능력이 현저히 적음을 알 수 있었다.

### 3. HTML 기초
- 웹페이지를 구성하는 가장 기초적인 구조에 대해서 다시 복습해보는 계기가 됐다.
    - Box
        - div : 다목적 박스, 내용들을 하나의 그룹으로 묶을 때 사용
        - span : 텍스트용 작은 박스, 특정 글자만 꾸미거나 그룹지을 때 사용
        - header : 머리말, div와 똑같지만 상단 정보임을 명확히 부여
        - footer : 꼬리말, div와 똑같지만 하단 정보임을 명확히 부여
        - section : 의미 있는 구역, 하나의 독립적 주제를 가진 덩어리 구역을 나눌 때 사용
    - Text
        - h1 ~ h6 : 제목(Heading), 글자가 작을수록 굵고 큼
        - p : 문단(Paragraph), 일반적인 줄글 작성, 위아래 여백 자동 생성
        - a : 링크(Anchor), 텍스트에 하이퍼링크 탑재 가능
        - ul : 비정렬 목록(unordered list), 순서 없이 항목 나열
        - ol : 정렬 목록(ordered list), 순서대로 항목 나열
        - li : 목록 항목
    - Input & Form
        - input : 입력창, 속성에 따라 Text, Password, Checkbox 등으로 사용자로부터 입력값을 받음
        - button : 버튼, 클릭 가능
        - form : 데이터 묶음, 여러 개의 input과 button을 하나로 묶어 데이터 제출할 때 사용
    - Media
        - img : 이미지를 넣음, src="경로"
        - video : 동영상을 넣음, src="경로"
        - audio : 오디오를 넣음, src="경로"
    - Block과 Inline 차이
        - Block : div, p, h1 등, 가로 한 줄을 혼자 다 차지
        - Inline : span, a, img 등, 자기 내용물 크기만큼만 공간 차지
- 사실 프론트엔드는 취향에 맞지 않아 잠깐 배우고 말았었는데, 여전히 안 맞는 듯 하다. 미적 감각이 없기 때문인지는 잘 모르겠다. 
- 유명한 컴퓨터공학의 유머 중 하나, "HTML은 프로그래밍 언어가 아니다."라고 말하며 화내기, 아니면 컴공에게 HTML 코딩 한다 하기. 난 이 유머가 정말 마음에 든다.
- 중학교 정보 시간에 HTML을 잠깐 배운 적이 있었다. 그때는 정보 선생님께서 이게 프로그래밍이라고 말씀해주셨는데, 지금 와서 생각해보니 정말.. 선생님이 왜 그러셨을까.

### 4. CSS 기초
- HTML 웹페이지에 미적 요소를 넣어주는 CSS에 대해서 여러 가지를 복습하거나 새로 배울 수 있었다.
    - 선택자 (Selector)
        - 태그 선택자 : 태그 { 속성: 값, ... }
        - 클래스 선택자 : .클래스명 { 속성: 값, ... }
        - 아이디 선택자 : #아이디명 { 속성: 값, ... }
    - 박스 모델 (Box Model)
        - Content : 텍스트나 이미지가 들어가는 내용물 자리
        - Padding : 콘텐츠와 테두리 사이에 여백
        - Border : 박스 테두리
        - Margin : 박스와 박스 사이에 여백
    - 속성 종류
        박스 모델 자체 조작
            - width : 너비 조정 (px 또는 %)
            - height : 높이 조정 (px 또는 %)
            - padding : 콘텐츠와 테두리 사이 여백
            - margin : 박스와 박스 사이 여백
            - box-sizing : 여백과 테두리를 지정한 크기 안에 포함시킬지 결정
        - 색상 및 배경
            - color : 글자 색상 바꿈
            - background-color : 박스의 배경색 지정
            - background-image : 배경에 이미지 지정 (url("경로"))
            - 그라디언트
                - background: linear-gradient(방향, 색상1, 색상2, ...)
                - background: radial-gradient(circle, 색상1, 색상2, ...)
        - 글자 및 폰트
            - font-size : 글자 크기
            - font-weight : 글자 굵기
            - font-style : 글자 스타일 (normal, italic, oblique, bold, ...)
            - text-align : 정렬 (left, right, center)
            - line-height : 행간 설정
            - letter-spacing : 글자 간격 설정
        - 테두리 및 모서리
            - border : 박스 테두리 (border: 굵기 종류 색상)
            - border-radius : 모서리에 라운딩
            - box-shadow : 박스에 그림자 넣음
        - Position
            - static : 원래 있던 그 자리
            - relative : 내 원래 자리를 기준으로 이동
            - absolute : 내가 정한 기준점을 따라 이동
            - fixed : 화면에 붙어서 움직이지 않음
- HTML만 있었다면, 웹페이지는 정말 못 생겼을 거 같다. 정말 웹페이지를 드라마틱하게 변할 수 있게 해주는 듯 하다.
- 근데 그만큼 양이 엄청 많다. 힘들다...

### 5. Javascript 기초
- HTML과 CSS로 웹페이지를 예쁘고 가독성 좋게 구성했다면, 이제 요소에다가 값을 넣고빼거나 백엔드 서버에 요청을 넣어서 값을 넣거나 빼거나 해야할 건데, 그걸 도와주는 게 자바스크립트다.
- 자바스크립트도 배운 적이 있었는데 이번 강의를 통해서 다시 복습하는 계기가 됐다.
    - 변수 (Variable)
        - var : 계속 새롭게 선언해도 사용 가능 -> 버그 유발 가능성 높음
        - let : 변할 수 있는 변수, 선언된 상태로 새롭게 선언하면 오류 발생
        - const : 변할 수 없는 수, 선언도 변경도 불가
    - 데이터 타입
        - 문자열 (String)
            - 큰따옴표 안 작은따옴표를 사용하거나, 작은따옴표 안에 큰따옴표를 사용할 수 있음.
            - 같은 따옴표를 사용하지 못함.
        - 숫자 (Number) : 따옴표로 감싸고 있지 않은 숫자, 모든 수 체계를 지원하므로 int, float 등이 없음
        - 불리언 (Boolean) : True / False
        - undefined : 선언만 한 상태
        - null : 선언은 했으나 값이 비어있음을 명시적으로 의미할 때
        - 배열 (Array)
            - '타입 변수명 = [원소1, 원소2, ...]'
            - 값은 index로 접근 -> arr[index], index는 0부터 시작
        - 함수
            - 함수도 데이터 타입이므로 변수에 담을 수 있음
            - 'fuction 함수명(매개변수1, 매개변수2, ...) { 로직 }'
            - '변수타입 변수명 = (매개변수1, 매개변수2, ...) => { 로직 }'
        - 객체 (Object)
            - '타입 변수명 = { 요소1=값1, 요소2=값2, ... }'
            - 값은 key로 접근 -> obj.key
            - 파이썬의 dictionary와 구조는 닮았지만 접근 방법이 다름
            - 값에 함수도 담을 수 있음
    - Property
        - 문자열
            - 변수.indexOf(문자열(찾을 문자열), 순서(n)) : 찾을 문자열 중 n번째 나온 순서의 인덱스 반환
            - 변수.length : 문자열 길이 반환
            - 변수.charAt(index) : index번 째 문자 반환
            - split(기준 문자열) : 문자열을 기준 문자열로 나눠 배열로 반환
        - 배열
            - 변수.length : 배열 길이 반환
            - 변수.push(원소) : 맨 끝 원소 추가
            - 변수.unshift(원소) : 맨 앞 원소 추가
            - 변수.pop : 맨 끝 원소 제거
            - 변수.splice(n, i) : 인덱스 n부터 i개 원소 삭제
        - 수학 (표준 내장 객체)
            - Math.abs(값) : 절댓값 반환
            - Math.random() : 0 < n < 1인 무작위 숫자 n 반환
            - Math.floor(값) : 인수로 전달받은 값과 같거나 작은 수 중에서 가장 큰 정수 반환
            - random과 floor를 통한 정수 랜덤 숫자
                - Math.floor(Math.random() * r) : 0 <= n <= r인 n 반환
            - Math.round(실수) : 소수점 첫째 자리에서 반올림
        - 데이터 타입 변환 (Casting)
            - typeof 변수 : 변수의 데이터 타입 반환
            - Number(변수) : 변수를 숫자로 변환
            - String(변수) : 변수를 문자열로 변환
            - parseInt(문자열) : 문자열을 정수로 변환
            - parseFloat(문자열) : 문자열을 실수로 변환
    - 연산
        - 비교
            - == : 값이 같음
            - === : 값이 같음 & 데이터 타입이 같음
            - ===을 사용하는 것이 더 안전?
        - 3항
            - (조건) ? n : m => 조건이 참일 경우 n, 거짓일 경우 m으로 결정
    - 반복문
        - obj.keys() : key값만 추출
        - obj.vlaues() : value값만 추출
        - for (const key in obj) { 로직 }
        - for (const item of arr) { 로직 }
        - arr.forEach((value, index)) => { 로직 } : arr의 원소와 인덱스를 차례대로 순회하여 로직 작동
- 태생이 데이터 타입의 명시가 없다보니 뭔가 엄청 다양하게 사용할 수 있는데, 타입이 없다 보니 코드 작성하는 게 너무나도 어렵다.
- 아마 타입이 없는 점으로 인해 타입스크립트가 탄생하지 않았나 싶다. 타입 명시하면 신경 쓸 게 하나 늘었지만 명확하고 빌드 타임도 많이 줄어들 거 같은 느낌이다.
- 함수도 Object로 처리되는 점에 대해서 신기했다.
