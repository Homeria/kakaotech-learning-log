### RAG(Retrieval Augmented Generation)
- Retrieval : (내제된) 정보를 검색하다.
- 포인트
    - 보관한 데이터와 사용자 프롬프트는 모두 문자열을 숫자로 Embedding한다!
    - Embedding을 완료한 보관 데이터와 사용자 프롬프트 간의 유사도를 계산해서 필요한 데이터만 참고한다!
    - Vectorization(Embedding)의 기준을 직접 정할 수 있다!
        - 임베딩 모델 선택
- 문제점 : 원하는 게 검색이 잘 안된다 == 매칭에 문제가 있다 => 검색 방법을 개선해볼까?

### 성능 개선을 해볼까?
- 질문 정제
    - 사용자의 질문 의도를 더욱 명확하고 체계적으로 개선
    - 단일 질문 또는 tool call의 경우에 대화의 맥락을 파악해서 질문을 정제
    - invoke된 데이터(질문)를 그냥 동작하지 않고 질문의 의도를 추출(ex. meta-CoT, system prompt, etc)
- 검색 과정 개선
    - Hybrid Search
        - 검색(Search) + Retrieval
        - 키워드를 추출해서 검색을 하도록 함
        - 검색 결과
            - keyword 검색
            - Retrieval 검색 결과
- 검색 결과 정제
    - 검색 결과들을 통째로 짱박으면 성능이 별로..?
    - Reranking : 검색 결과의 중요도를 모델이 다시 정리하도록 하는 방법 
    - 검색 결과를 정리(정제)하기만 해도 성능이 올라간다는 실험들이 있어 무시할 수 없음
