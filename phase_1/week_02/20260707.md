
### 구조화된 출력
- LLM은 기본적으로 `자연어`를 출력한다.
- 만약 기존 시스템에 LLM(Agent)를 도입한다면?
    - LLM은 자연어를 뱉는다.
    - 그래서 생성된 결과(자연어)를 다시 파싱해야 한다.
- LLM이 우리가 원하는 형태의 결과를 뱉도록 `구조화된 출력(Structured outputs)`을 만들자!
    - ex. JSON
        - 예시 : { name: "철수", time: "09:00", location: "학교" }
        - 장점 : 간단한 프롬프트, JSON 형식으로 쉽게 변환 받음
        - 단점 : key가 누락될 수 있음 (구조 붕괴) -> 파싱 등 데이터 가공 및 CRUD에서 잠재적 오류 발생 여지 있음
        - 해결 : Framework(ex. Langchain, pydantic, etc)에서 구조화된 출력에 대한 검사 진행 (의존!)
    - Pydantic class
        - 장점 : key 누락 방지 가능 (구조를 충족하지 않으면 오류 반환)
        - 단점 : 파싱 단계가 길고, 특히 JSON을 파싱하는 과정에서 오류가 많이 발생함

### Prompt Engineering
- 본래 명칭은 Learning 분야에서 사용함
    - `zero shot learning` : 기존 모델이 추가적으로 학습하지 않고 정보를 분류 및 생성 진행
    - `few shot learning` : 약간의 파인튜닝으로 분류 및 생성 진행
- 프롬프트도 비슷한 의미로 사용함
    - `zero shot prompt`
        - 번역 : 예시가 없는 프롬프트
        - Q. 아래 문장의 감정분석을 진행하세요 -> "이 영화는 재미있다"
        - A. 긍정
    - `few shot prompt`
        - 번역 : 예시가 있는 프롬프트
        - Q. 아래 문장의 감정분석을 진행하세요 -> "이 영화는 재미있다", "예시: "이 영화를 다시 보고 싶다" - 긍정, "이 영화는 별로다" - 부정"
        - A. 긍정
        - JSON으로 예시를 구성해서 프롬프트를 구성할 수 있음

### LLM & LangChain 파싱 (Tool Strategy)
- Tool Strategy 활성화시 LangChain 우선, 비활성화시 LLM 우선 하고 실패하면 LangChain 사용.
- 프롬프트 입력 후에 대기 시간이 길어진다면 파싱 실패를 실패하고 있음을 내포하고 있음.
- 제공자 변경 또는 프롬프트 변경을 통해 파싱 실패 해결 가능.
