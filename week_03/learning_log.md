## 학습 내용
### 1. DOM(Document Object Model)과 이벤트
- 다양한 종류의 tag가 있는 HTML, 방대한 양의 꾸미기 속성이 있는 CSS, 타입이 엄격하지 않고 함수조차 object로 취급되는 js와의 싸움을 이겨내고 본격적으로 프론트엔드다운 설계에 들어가기 위한 기초 내용이다.
- DOM은 Tree 형태로 루트, 부모, 자식, 노드의 개념을 그대로 사용한다. 태그 하나를 노드라고 보고, 태그 안에 태그를 자식으로 취급한다.
- document 객체를 통해 오브젝트에 접근할 때는 다음의 방법으로 접근할 수 있다.

    | 구분 | 메서드 | 반환 대상 |
    |---|---|---|
    | 하나 선택 | `getElementById()` | 특정 id의 요소 하나 |
    | 하나 선택 | `querySelector()` | CSS 선택자에 맞는 첫 번째 요소 |
    | 모두 선택 | `getElementsByTagName()` | 특정 태그의 모든 요소 |
    | 모두 선택 | `getElementsByClassName()` | 특정 class의 모든 요소 |
    | 모두 선택 | `getElementsByName()` | 특정 name 속성값의 모든 요소 |
    | 모두 선택 | `querySelectorAll()` | CSS 선택자에 맞는 모든 요소 |

- 오브젝트에 접근해서 요소를 변경하는 방법에는 다음이 있다.

    | 사용 예시 | 설명 |
    |---|---|
    | `요소.style.스타일속성 = "200px"` | 요소의 스타일 조회 및 변경 |
    | `요소.innerHTML = "<li><span>hello</span></li>"` | 요소 하위의 HTML 조회 및 변경 |
    | `요소.innerText = "Hello Elice"` | 요소 하위의 텍스트 조회 및 변경 |
    | `요소.getAttribute("placeholder")` | 요소의 HTML 속성 조회 |
    | `요소.setAttribute("min", "20")` | 요소의 HTML 속성 변경 |
    | `요소.classList` | 요소의 class 수정 |

- 요소를 생성하고 추가하는 방법은 다음이 있다.

    | 메서드 사용 예시 | 설명 |
    |---|---|
    | `document.createElement("form")` | 해당 태그의 HTML 요소를 생성 |
    | `document.write("Hello World")` | 텍스트를 화면에 출력 |
    | `요소.appendChild(node)` | 해당 요소 내부 가장 마지막에 node 추가 |

- 이벤트는 HTML 요소에 대한 사건의 발생을 의미하며, 종류에는 다음이 있다.

    | 이벤트 종류 | 설명 |
    |---|---|
    | 마우스 이벤트 | 마우스 조작과 관련된 이벤트 |
    | 키 이벤트 | 키보드 조작과 관련된 이벤트 |
    | 폼 이벤트 | `form` 태그 관련 동작에 대한 이벤트 |
    | 로드 관련 이벤트 | 페이지나 리소스가 로드될 때 발생하는 이벤트 |
    | 창 관련 이벤트 | 브라우저 창 크기 변경 등과 관련된 이벤트 |

- 이벤트 핸들러는 이벤트가 발생하면 특정 동작을 수행한다. 즉, 이벤트가 트리거가 된다.
- 이벤트 핸들러의 등록 방법은 다음과 같다.

    | 방법 | 설명 | 권장 여부 |
    |---|---|---|
    | HTML 속성에 등록 | HTML 요소의 `on이벤트명` 속성에 직접 동작을 추가 | 권장되지 않음 |
    | node 객체 프로퍼티에 등록 | node 객체의 `on이벤트명` 프로퍼티에 함수 등록 | 사용 가능 |
    | `addEventListener()` 사용 | 이벤트명과 핸들러 함수를 인수로 전달 | 권장 |

- 이벤트 핸들러의 제거는 removeEventListener() 메서드를 사용한다.

- event 객체는 이벤트 핸들러 함수에 첫 번째 인수로 전달되는 객체로, 이벤트에 대한 정보를 담고 있다. 

    | event 객체 종류 | 설명 |
    |---|---|
    | 마우스 이벤트 | 마우스 위치, 클릭 정보 등 |
    | 키 이벤트 | 누른 키에 대한 정보 등 |
    | 이벤트 타겟 | 이벤트가 실제로 발생한 대상 요소의 node 객체 |
    | preventDefault | form 태그에서 submit 버튼의 기본 동작을 차단 |

- 이벤트는 DOM 트리에 따라 전파되는데, 이를 이벤트 전파라고 한다.
- 예를 들어, 이벤트는 가장 하위 요소에서 버튼 클릭 이벤트가 발생했을 때 그 이벤트는 DOM 트리를 통해 여러 상위 요소로 전달된다.
- 이러한 이벤트 전파는 크게 세 단계로 나눌 수 있다.

    | 단계 | 설명 |
    |---|---|
    | Capturing Phase | 이벤트가 상위 요소에서 하위 요소 방향으로 내려가는 단계 |
    | Target Phase | 이벤트가 실제 대상 요소에 도달한 단계 |
    | Bubbling Phase | 이벤트가 대상 요소에서 상위 요소 방향으로 올라가는 단계 |

- Bublling Phase의 경우에는 부모 요소의 이벤트 핸들러까지도 실행될 수 있으므로, 이를 막고 싶다면 event.stopPropagation()을 사용하여 전파를 차단한다.

- 사실 DOM과 이벤트 관련해서는 크게 어렵지 않았다. 암기할 게 많을 뿐이다... JS가 자유도가 높은 언어인 만큼 기상천외한 방식으로 동작하는 듯 해 보인다. 그래서 타입스크립트가 만들어진 게 아닌가 싶다..


### 2. ES6와 비동기

- JS는 시대를 거쳐오며 많은 문법 변화들이 이루어졌다. 주요 문법으로는 다음이 있다.

    | 문법 | 예시 | 설명 |
    |---|---|---|
    | `let`, `const` | `let name = "Elice";` | 변수를 선언하는 새로운 방식 |
    | 화살표 함수 | `() => { ... }` | 함수를 간결하게 작성하는 문법 |
    | 구조 분해 할당 | `const { name, age } = user;` | 객체나 배열의 값을 쉽게 변수에 할당 |
    | Spread 문법 | `const arr = [...arr1, ...arr2];` | 배열이나 객체를 펼쳐서 사용 |
    | 템플릿 리터럴 | `` `Hello ${name}` `` | 문자열 안에 변수나 표현식을 쉽게 삽입 |
    | 옵셔널 체이닝 | `user.contact?.email` | 존재하지 않는 값에 안전하게 접근 |
    | 프로퍼티/메서드 축약 | `{ name, age }` | 객체 작성 시 중복을 줄이는 문법 |
    | 배열 메서드 | `forEach`, `map`, `filter`, `reduce` | 배열 데이터를 효율적으로 처리 |

- 변수 선언으로는, 불변일 경우 `const`, 가변일 경우 `let`을 사용한다.
- `var`의 경우에는 특이하게도 함수 레벨 스코프를 지원하며, `if`문 내부에서 선언한 변수는 블록 밖에서도 접근될 수 있다. 블록 안에서 전역 변수를 선언한 것과 같은 효과인 셈인건가?

- 문자열 연결로는 `+` 연산이 있지만, 템플릿 리터럴로 하면 "" 또는 ''로 감싸던 걸 ``로 수정하고 `${변수명}` 형식으로 쓰면, python의 `f"{변수명}"` 형식과 비슷하게 동작한다.

- 배열 메서드 종류로는 다음이 있다.
    - 고차 함수 : 함수를 인자로 받거나 함수를 반환하는 함수
    - 콜백 함수 : 함수를 인자로 받는 고차 함수에서, 인자로 넘겨주는 함수
         | 메서드 | 설명 |
        |---|---|
        | `forEach` | 각 요소에 대해 콜백 함수를 한 번씩 실행 |
        | `map` | 각 요소를 변환하여 새로운 배열 반환 |
        | `filter` | 조건을 만족하는 요소만 모아 새로운 배열 반환 |
        | `reduce` | 각 요소를 누적 계산하여 하나의 결과 반환 |

- js에서는 내장 객체가 존재하며, 종류로는 다음이 있다.

    | 객체 | 설명 |
    |---|---|
    | `window` | 브라우저 창을 나타내는 객체 |
    | `document` | 브라우저에 로드된 웹 페이지 객체 |
    | `Number` | 숫자 자료형을 다루기 위한 객체 |
    | `Math` | 수학 연산과 상수를 제공하는 객체 |
    | `Date` | 날짜와 시간을 다루기 위한 객체 |
    | `String` | 문자열을 조작하기 위한 객체 |
    | `JSON` | 객체를 직렬화/역직렬화하기 위한 객체 |

- js 코드는 js 엔진을 통해 파싱되고 실행되는데, Chrome에서는 V8 엔진을 사용한다.
- 엔진은 코드 실행 전에 실행 컨텍스트를 생성하는데, 이는 코드가 실행되는 환경을 정의하며, 변수, 함수 선언, this 바인딩 등의 실행에 필요한 정보를 관리하는 개념이다.

    | 단계 | 설명 |
    |---|---|
    | 생성 단계 | 변수 선언문과 함수 선언 등을 먼저 저장 |
    | 실행 단계 | 나머지 코드를 실행하고 변수 값 할당 |

- 실행 컨텍스트는 콜 스택(Call Stack)에서 관리된다.

- js는 단 하나의 콜 스택을 가지기 때문에, 싱글 스레드 기반 언어라고 할 수 있다.

- 싱글 스레드는 진행 중인 작업이 종료되기 전까지는 이후 작업을 시작하지 못하는 블로킹 문제가 발생하며, 이를 해결하기 위해 처리 방식을 달리하여 동기/비동기로 방식을 나눌 수 있다.

    | 구분 | 동기 처리 | 비동기 처리 |
    |---|---|---|
    | 실행 방식 | 순차적으로 실행 | 작업 완료를 기다리지 않고 다음 작업 실행 |
    | 대기 여부 | 현재 작업이 끝날 때까지 대기 | 대기하지 않음 |
    | 문제점 | 블로킹 발생 가능 | 실행 순서를 이해하기 어려울 수 있음 |
    | 결과 처리 | 바로 반환값 사용 | 콜백, Promise, async/await 사용 |

    | 기능 | 예시 |
    |---|---|
    | 타이머 함수 | `setTimeout`, `setInterval` |
    | Ajax | `XMLHttpRequest`, `Fetch API` |
    | 이벤트 핸들러 | `addEventListener` |

- 비동기 처리를 위해 이벤트 루프와 테스트 큐(이벤트 큐, 콜백 큐라고도 한다)를 사용한다.

    | 개념 | 설명 |
    |---|---|
    | Call Stack | 현재 실행 중인 작업이 쌓이는 공간 |
    | Task Queue | 비동기 함수의 콜백 함수가 잠시 저장되는 큐 영역 |
    | Event Loop | 콜 스택이 비었을 때 태스크 큐의 작업을 콜 스택으로 이동 |
    | Queue | FIFO 방식의 자료구조 |

- `Promise`를 사용하여 비동기 처리와 실패를 명확하게 다룰 수 있다.

    - 생성 : new.Promise(function(resolve, reject) { ... })
        - resolve : 비동기 처리 성공
        - reject : 비동기 처리 실패

    - 상태
        | 상태 | 설명 |
        |---|---|
        | `pending` | 비동기 처리가 완료되기 전, 대기 상태 |
        | `fulfilled` | 비동기 처리가 완료되었고 성공한 상태 |
        | `rejected` | 비동기 처리가 완료되었고 실패한 상태 |

    - 상태 변화
        | 실행 | 상태 변화 |
        |---|---|
        | Promise 생성 직후 | `pending` |
        | `resolve()` 실행 | `pending` → `fulfilled` |
        | `reject()` 실행 | `pending` → `rejected` |

    - 처리
        | 메서드 | 설명 |
        |---|---|
        | `.then()` | 비동기 성공 및 실패 후 처리 |
        | `.catch()` | 비동기 실패 후 처리 |
        | `.finally()` | 성공/실패 여부와 관계없이 이후 처리 |

    - `Promise.all` vs `Promise.allSettled`
        | 구분 | `Promise.all` | `Promise.allSettled` |
        |---|---|---|
        | 실패 시 동작 | 하나라도 실패하면 즉시 전체 reject | 성공/실패와 관계없이 끝까지 기다림 |
        | 반환값 | 성공 값들의 배열 | status 객체들의 배열 |
        | 사용 시점 | 모두 성공해야 의미 있을 때 | 일부 실패를 허용할 때 |
        | 동작 방식 | Fail-Fast | Wait-All |

- async/await은 `Promise`의 계속된 체이닝에 의한 가독성 저하를 해결할 수 있다.
    - await : 비동기 처리가 완료될 때까지 기다린 후, resolve된 값을 반환
    - async : 항상 반환값을 resolve하는 Promise를 반환

- 에러 처리는 `try ... catch`로 할 수 있으며, `try`만 단독 사용하진 못하고, finally를 붙이면 에러 여부와 상관업이 실행되도록 하 ㄹ수 있다.

- 이 파트는 양이 어마무시하게 많다. 대부분 언어의 자유도에서 오는 방식의 차이이고, 이를 더 편리하게 하기 위해 진화해와 지금의 ES6를 구축하게 된 계기가 된 거 같기도 하다.
- 특히 Promise라는 개념이 많이 어색하게 느껴졌으며, 아직 이해보다는 암기에 가까운 것 같다. 마치 양자역학같다.

### 3. React 입문
- Vanilla JS만으로 개발을 한다면, 상태가 바뀔 때마다 개발자가 직접 DOM을 찾아 수정해야 한다.
- 이 과정에서 DOM 추적이 복잡하고, 코드가 길어지고, 실수가 늘어나고, 유지보수가 어려워진다.
- 상태가 바뀔 때마다 DOM을 수정하기보다는, 상태를 만들어 공유하면 어떨까 하는 아이디어로 만들어진 것이 React의 useState이다. 일종의 공유 그릇을 만들어두고 이 상태가 바뀌면 React가 알아서 재렌더링 하는 방식인 셈이다. 이 모습은 변수의 스코프와 닮아있는 듯 하다. 마치 전역 변수 같은 느낌이다.
- React는 상태가 바뀐다고 모든 DOM에 대하여 재렌더링을 하지 않는다. 가상 DOM을 만들어 이전 가상 DOM과 비교해 실제 변경된 부분만 반영한다. 깃허브의 커밋 방식과 비슷해보인다.
- JSX는 문법 확장으로, 별도의 도구를 통해 일반 JS 코드로 변환한다.

- JSX의 핵심 규칙은 다음과 같다.

    | 규칙 | 설명 | 예시 |
    |---|---|---|
    | 최상위 요소는 하나 | 여러 요소를 반환하려면 하나로 감싸야 함 | `<div>...</div>` 또는 `<>...</>` |
    | `class` 대신 `className` | JSX는 JavaScript 문법이므로 `class` 예약어와 충돌 방지 | `<div className="container">` |
    | 닫는 태그 필수 | 일반 태그와 self-closing 태그 모두 닫아야 함 | `<img src="a.jpg" />` |
    | `{}` 안에는 표현식만 | if문, for문 같은 문은 직접 넣을 수 없음 | `{isOpen ? <A /> : <B />}` |

- 컴포넌트는 독립적이고 재사용 가능한 UI 조각으로써, React 앱은 여러 컴포넌트를 조합하여 만들어진다. 이게 가능한 이유는 상태 변화를 알아서 감지해 차이점만 반영해주기 때문에 별도의 하위 요소로의 데이터 갱신 주입이 필요없기 때문이다. 
- 컴포넌트의 이름은 반드시 대문자로 시작해야 하는데, 이는 HTML 태그와 겹치지 않기 위해서이다.

- Props는 부모 컴포넌트가 자식 컴포넌트에게 전달하는 데이터이다. 읽기 전용으로 변수 그릇을 넘겨주는 형태인 셈이다. 그래서 부모 컴포넌트에서 선언된 useState의 변화가 발생해도 자식 컴포넌트에서는 별다른 조치 필요없이 재렌더링된다. 읽기 전용이 포인트이다.
- Props의 특징은 다음과 같다.

    | 특징 | 설명 |
    |---|---|
    | 부모 → 자식 | 데이터는 부모에서 자식 방향으로 전달된다. |
    | 읽기 전용 | 자식은 props를 직접 수정할 수 없다. |
    | 재사용성 향상 | 같은 컴포넌트에 다른 props를 전달해 여러 화면을 만들 수 있다. |
    | 구조 분해 할당 가능 | `{ name, role }`처럼 필요한 값만 바로 꺼내 쓸 수 있다. |
